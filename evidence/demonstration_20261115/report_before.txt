4. Curriculum ingestion and agentic RAG
Six synthetic curriculum files produce 8 chunks in the measured corpus. The maximum actual chunk
size is 500 cl100k_base tokens. Adjacent windows overlap by exactly 50 token positions; final windows
may be shorter than 500. Unicode boundary checks prevent broken UTF-8. Missing exact tokenization
raises an explicit error instead of silently estimating.
The hash embedder normalizes deterministic term and bigram features. ChromaDB stores vectors, text
and source metadata. It is actual vector retrieval, but it is not a verified hosted embedding model.
Metadata records token_start, token_end, chunk index, token count and overlap.
Advisor flow: retrieve, critique sufficiency, reformulate if insufficient, retrieve again, then answer or
abstain. The graph permits at most three searches, including the initial search. Offline sufficiency uses
term coverage; live LLM reflection remains unverified.
Answers attribute source files. This audit corrected synthetic material that previously implied thread IDs
alone guaranteed privacy or that a host subprocess was an adequate sandbox. Source hashes
accompany the final benchmark.
Code: src/tokens.py; src/tools/rag_retriever.py; src/agents/advisor_agent.py. Evidence: tests/test_rag.py; exact-overlap
regression; evidence/benchmark/rag_latency.json.

8. Identity, memory and learner isolation
MockIdentityProvider issues random sessions during trusted local application startup. Learner requests
cannot select identity or role. This simulates an identity provider for the POC; it does not authenticate
real people and must not be exposed as a username-only public login endpoint.
OrchestratorService owns opaque thread allocation and the private MemorySaver graph. Strict request
validation rejects learner_id, thread_id, raw messages, approval, profile and code-state injection.
Snapshot access resolves the requesting session and returns an explicit public field allowlist.
Database tools independently enforce the bound learner context, even if a prompt supplies a different
ID. Parameterized operations prevent SQL injection; ad-hoc SQL remains disabled. Real tool execution
tests demonstrate ContextVar propagation and cleanup.

9. Human-in-the-loop authorization
A tier-1 placement pauses using LangGraph interrupt. The learner sees only a pending message; raw
draft, profile and tool responses stay internal. The default demo never resumes an approval
automatically.
The reviewer session must have learner scope. Strict Pydantic review requires a pending ID, boolean
approval and rationale. The service compares the current pending checkpoint and complete
structured-recommendation hash, binds trusted review context, atomically consumes the pending action
and resumes under a lock.
